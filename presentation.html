[NEW] Core Feature 1

글자 단위 실시간 공동 편집 (Operational Transformation)

두 사람이 같은 곳을 동시에 고쳐도 덮어쓰기 없이 모두 같은 결과로 수렴

✍️ 동작 원리

  • 서버가 순서를 정함: 모든 편집에 리비전 번호를 매기고 /ws/live 로 중계 (ot.py · livedoc.py)
  • 클라이언트 변환: 전송 중인 편집·대기 중인 편집을 상대 편집에 맞춰 변환해 같은 문서로 수렴
  • 자가 복구: 문서 길이·체크섬이 어긋나면 서버 기준으로 자동 재동기화
  • 한글 입력 보호: 조합 중인 글자는 끝난 뒤 원격 편집을 적용해 입력이 깨지지 않음

👀 기존 방식과의 차이

  • 저장 후 갱신 ➔ 글자 단위 즉시 반영: Enter·저장 전에도 팀원이 치는 글자가 보임
  • 팀원 커서·입력 위치 표시: 사람마다 색이 있는 작은 아바타 커서
  • 자체 되돌리기(Undo): 남의 편집이 섞여도 내 편집만 정확히 되돌림
  • 충돌 알림 최소화: 파일 저장 충돌 대화상자가 거의 필요 없음

[NEW] Core Feature 3

내 PC 러너: 내 컴퓨터에 설치한 언어로 실행

서버에 없는 언어·버전·라이브러리(pip)·창(GUI)을 한 줄 설치로 해결

🖥️ 어떻게 쓰나 (사용자 3단계)

  • 1. 워크스페이스의 🖥️ 내 PC → 터미널 여는 법과 한 줄 명령이 OS별로 표시됨
  • 2. 그 한 줄을 터미널에 붙여넣기 (어느 폴더에서든 OK — 설치·자동 시작·연결 코드까지 한꺼번에)
  • 3. 창이 알아서 ✓ 연결됨 → ▶ 옆에서 내 PC · Java 17 선택
  • 새로 설치한 언어는 ▶ 실행할 때 자동으로 다시 찾음 · pip 미설치면 설치 명령을 콘솔이 안내

🔒 안전 설계

  • 내 컴퓨터(127.0.0.1)에서만 접속을 받음 — 같은 와이파이의 다른 사람도 못 씀
  • 허용 사이트(Origin)·Host 검사 + 연결 코드로 다른 사이트의 호출·DNS 우회 차단
  • 팀원이 고친 코드는 실행 전에 "확인했어요" 동의를 받음, 처음엔 격리되지 않음을 안내
  • "내 PC 실행 사용" 스위치로 언제든 서버로만 실행 · 폰·PWA는 서버 언어만

서버에는 화면이 없다 ➔ 서버는 컴파일만, 창은 브라우저가 그린다 (PC · 모바일 · PWA)

☕
① Swing 코드
javax.swing 을 쓰는 .java 파일에서 ▶ 실행
⚙️
② 서버: javac 컴파일만
jar 로 묶어 전달 · 서버 메모리 약 100MB
🌐
③ 브라우저: CheerpJ

버튼 클릭·System.out 이 콘솔로

🧠 왜 이 방식인가 (실측 근거)

  • 서버 실행 시 HeadlessException — 서버에 화면이 없음
  • 운영 서버 메모리 1GB (여유 약 400MB) ➔ 사용자마다 가상 화면(250~400MB)을 띄우면 서버 다운 위험
  • 브라우저 실행 ➔ 서버 부담 0, 폰·PWA까지 동일하게 동작

🛡️ 보안 · 한계 · 라이선스

  • 컴파일된 class 상수 풀 검사로 리플렉션·JS 연결(JSObject)·native 차단, 창은 로그인 정보를 모르는 별도 iframe(별도 출처 옵션)
  • 한계: Swing/AWT 중심 (JavaFX·Scanner 입력 미지원), 첫 로딩 약 30초 후 캐시
  • CheerpJ Community 라이선스(개인·1인 회사 무료, 크레딧 표기) — 상업화 시 유료 라이선스 검토
Core Feature 5

AI 팀 비서: 대화에서 일정·회의록을 자동으로

명령어를 외울 필요 없이 AI 이름을 부르거나, 나만 보는 AI 탭에서 편하게 대화

팀 채팅 이름으로 부르는 AI

프로필에서 정한 AI 이름을 부르면 대화체로 일정 등록·회의록 작성·정리를 해 줍니다. 만든 일정은 되돌리기·삭제 확인 버튼이 붙습니다.

"두레야 금요일 3시 스프린트 회의 잡아줘"
➔ 캘린더 등록 완료 · 팀원 화면 즉시 동기화
🔒 나만 보는 AI 개인 대화 탭

이름 없이도 답하고, 내 질문·AI 답은 나에게만 보입니다. 팀 채팅·실시간 알림·다른 사람의 AI 자료로 새지 않도록 서버에서 분리했습니다.

서버: scope=ai 는 본인에게만 전달

일정 감지 회의록·채팅 ➔ 캘린더

"제가 금요일까지 할게요" 같은 말에서 담당·기한을 찾아 일정 카드로 제안하고, 추가하면 프로젝트 캘린더에 들어갑니다. 회의록은 노션처럼 쓰고 AI가 정리합니다.

프로젝트 단위로 캘린더·회의록·채팅 연동

[NEW] Core Feature 6

디스코드처럼: 팀 통화방 · 자동 재연결 · 효과음

팀원 브라우저끼리 직접 연결(WebRTC)해 지연을 최소화, 서버는 연결 신호만 중계

📞 통화방 기능

  • 프로젝트별 여러 방: 기본 방은 프로젝트 이름을 따라가고, 팀원이 방을 만들 수 있음 (프로젝트당 8개, 방당 6명)
  • 지연 표시: 연결 상태와 왕복 지연(ms)을 실시간으로 보여 줌
  • 프로젝트를 바꿔도 통화 유지: 디스코드의 채널 이동처럼 끊기지 않음
  • 자동 재연결: 신호 연결이 끊겨도 마이크를 유지한 채 최대 8회 재시도 + 15초 ping 으로 죽은 연결 감지

🔔 효과음 (파일 없이 브라우저가 생성)

  • 새 채팅 도착 · 내가 들어감(올라가는 소리)/나감(내려가는 소리)
  • 팀원 입장·퇴장 · 마이크 켜기·끄기
  • Web Audio 로 합성 → 소리 파일·저작권·용량 걱정 없이 PC·모바일·PWA 동일
  • 🔔 버튼으로 끄기, 방해금지 중에는 채팅 소리 없음, 내 메시지·AI 답변에는 울리지 않음
원인 분석으로 고친 버그: "통화방이 가끔 자동으로 나가진다" ➔ 프로젝트 전환 시 자동 퇴장하는 구조와 폴더 가져오기 후 다른 프로젝트로 다시 열리는 문제 ➔ 통화를 프로젝트에 고정 + 가져온 프로젝트 유지. (서버 12항목 · 클라이언트 로직 28항목 테스트)
Team Collaboration

팀 허브 · 초대 · 마이페이지 · 게스트 온보딩

더미 데이터 없이 실데이터만으로 동작, 초대 링크 하나로 멀리 있는 팀원도 합류

👥 팀 관리 (/app/team)

  • 실시간 팀원 상태 카드: 프로젝트별 접속 현황
  • 역할(RBAC): 팀장·부팀장·팀원, 팀장은 내보내기·권한 부여
  • 초대 링크: 기본 72시간 만료, 로그인 후 자동 합류 (정확한 이메일 검색은 횟수 제한)

DevOps & Production

AWS + Docker + Caddy: 실제 도메인으로 운영

duresync.cloud 에 배포해 팀원이 실제로 접속·사용하는 서비스

🚀 배포 절차

  • GitHub main ➔ 서버 git pull ➔ docker compose -f docker-compose.prod.yml up -d --build
  • Caddy 가 HTTPS 인증서를 자동 발급·갱신하고 FastAPI 로 프록시 (웹소켓 포함)
  • 데이터(data/)와 설치한 언어(langs/)는 볼륨으로 보존, 배포 전 백업
  • GitHub Actions 배포 워크플로우도 준비(서버 접속 정보를 등록하면 push 시 자동)

📏 자원 기반 설계 결정

  • 서버: 메모리 1GB · 디스크 28GB ➔ 실측 후 기능 방식을 선택
  • 무거운 작업은 사용자 쪽으로: 자바 GUI 는 브라우저 실행, 비표준 언어는 내 PC 러너
  • 이미지에는 핵심 언어만 넣고 나머지는 관리자 페이지에서 필요할 때 설치
  • 실시간 편집 방은 서버 메모리에 있어 워커 1개로 운영

Security by Design

사용자 코드를 돌리는 서비스의 6겹 보안

서버·내 컴퓨터·브라우저 어디서 실행되든 안전하도록 경로마다 방어선을 설계

① 서버 실행 격리

로그인 필수 · 서버 비밀(환경변수) 미전달 · 시간·출력·CPU·파일 크기 제한 · 프로세스 그룹 종료 · 공유 모드에서는 꺼짐

② 내 PC 러너

127.0.0.1 전용 · 허용 사이트(Origin)·Host 검사 · 연결 코드(파일 권한 0600) · 팀원이 고친 코드는 실행 전 동의

③ 브라우저 자바(GUI)

class 상수 풀 검사(리플렉션·JS 연결·native 차단) · 로그인 정보를 모르는 별도 iframe · 별도 출처(sandbox) 옵션 · javac 어노테이션 처리 끔

④ 계정·권한

JWT + 역할(RBAC) · 관리자 6자리 코드(잠금) · 서버 변경은 최고관리자만 · 감사 로그 · 탈퇴 7일 유예

⑤ 비밀·저장소 관리

.env·키·DB 는 git 제외 · 푸시 전 비밀 값 검사 · SSH 키 비공개 · 서버 데이터 백업 후 배포

⑥ 개인정보

나만 보는 AI 대화는 본인에게만 · 이메일은 정확 일치 검색만(횟수 제한) · 소셜 로그인 오류는 원인을 로그로 남김

🔍 직접 찾아서 막은 위험: 브라우저 자바(CheerpJ)에 JS 연결 통로(JSObject)가 있음을 시험으로 확인 ➔ 위험한 기능을 서버가 컴파일 단계에서 거절하고 창을 별도 iframe 에서 실행하도록 설계.
Engineering Depth

실제 개발·운영에서 원인을 재현해 해결한 4대 난제

"되는 것 같은데 가끔 안 된다"를 로그·재현·테스트로 끝까지 추적한 사례

CHALLENGE 01

PC에서만 소셜 로그인이 실패

같은 계정이 폰에서는 되고 PC에서만 실패. 서버 로그에 일회용 인증 코드가 두 번 사용된 흔적.

해결: 서비스 워커의 화면 이동 사전 요청이 콜백을 중복 호출함을 재현으로 확인 ➔ 사전 요청 해제 + 서버 중복 요청 방어(60초).
CHALLENGE 02

통화방이 가끔 자동으로 나가짐

특히 폴더를 가져온 직후. 연결 자체는 정상인데 앱이 스스로 통화를 종료.

해결: 프로젝트 전환 시 자동 퇴장하는 구조가 원인 ➔ 통화를 프로젝트에 고정, 연결 끊김은 마이크 유지 자동 재연결(최대 8회).
CHALLENGE 03

서버에서 자바 창(Swing) 실행 불가

HeadlessException. 가상 화면 방식은 사용자당 250~400MB, 서버 여유는 약 400MB.

해결: 서버 메모리를 실측해 방식을 바꿈 ➔ 서버는 컴파일만(약 100MB), 창은 브라우저(CheerpJ)가 그림. 위험 기능은 컴파일 단계에서 차단.
CHALLENGE 04

윈도우 한글 환경에서 러너 오류

한국어 콘솔(cp949)에서 시작 즉시 종료, 한글 사용자 이름 경로에서 자동 시작 오류.

해결: 못 찍는 글자를 대체 출력하고, 자동 시작을 유니코드를 그대로 쓰는 레지스트리 방식으로 교체 + cp949·cp1252 콘솔 재현 테스트.
