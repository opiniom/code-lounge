# frontend — DureSync 화면

서버가 `/app` 으로 내려주는 화면입니다. 예전엔 `index.html` 한 파일(약 8,600줄)이었고, 지금은 종류별로 나눠져 있습니다.

```
frontend/
├─ index.html            화면 뼈대(HTML 마크업)만. 스타일/스크립트는 서버가 묶어서 연결
├─ manifest.json         css / js 파일을 묶는 "순서" (새 파일을 만들면 여기에 추가)
├─ css/
│   ├─ base.css          색·글꼴 토큰, 공통 레이아웃
│   ├─ home.css · workspace.css · notes.css · calendar.css · events.css · community.css · mypage.css · admin.css · auth.css
│   ├─ notifications.css · components.css · editor.css(코드 에디터 테마)
│   └─ polish.css · widgets.css · presence.css · landing.css · splash.css · voice.css   (타이포·위젯 갤러리·내 상태·소개 첫 화면·앱 인사 화면·음성 입력)
└─ js/
    ├─ core/     theme · router(화면 주소) · home-landing · auth · settings · api(서버 연동·웹소켓) · session(로그인 전/후 전환) · splash(설치한 앱 인사 화면) · greeting(시간대별 인사) · prefs(내 설정 웹↔앱 동기화) · icons(공용 선 아이콘)
    ├─ shell/    menus · presence(내 상태) · notifications(알림·토스트)
    └─ pages/    home-widgets · events · workspace · chat · voice(음성으로 AI 부르기) · notes-sheet(회의록 작성·보기·수정 시트) · workspace-memo(코드 줄 메모) · workspace-keys(실행 단축키·설정에서 바꾸기) · call · team · notes · calendar · community · admin
```

## 음성으로 AI 부르기 (`js/pages/voice.js`)

채팅 입력줄의 마이크 버튼을 누르고 "두레야 내일 3시에 회의 잡아줘"처럼 말하면, 글로 바뀌어 **직접 친 것과 똑같이** 채팅 → AI 로 처리됩니다 (AI 호출어로 시작하면 1.6초 뒤 자동 전송, 그 안에 [취소]·글 수정 가능. 호출어 없이 말하면 입력칸에만 채워 줘요. '나만 보는 AI' 탭에서는 호출어 없이도 보냄).
- 브라우저 음성 인식(Web Speech)이 되면 그걸 쓰고, 안 되는 곳(아이폰 설치 앱 등)은 녹음 → `POST /api/ai/transcribe` (Gemini 받아쓰기, 서버에 `GEMINI_API_KEY` 필요, 사용자당 시간당 40회) 로 처리. 소리는 저장하지 않아요.
- 호출어 오인식('두래야', '듀레야')은 AI 이름(기본 이름 + 내가 정한 이름)에 맞게 보정합니다.

## 워크스페이스: 코드 줄 메모 · 실행 단축키

- **코드 줄 메모** (`js/pages/workspace-memo.js`, `api/routers/memos.py`): "이 파일 19번째 줄은 민수님이 고쳐야 해요" 같은 짧은 메모를 코드 줄에 남겨 팀이 같이 봐요.
  - **직접 달기**: 도구막대 `메모` 버튼 · 에디터 우클릭 · `Ctrl+Alt+M`(맥 `⌘⌥M`). 작은 한 줄 입력창에 적고 Enter 만 누르면 끝이고(창은 바로 닫혀요), 글 속에 `@민수`처럼 적으면 그 팀원이 담당자가 돼서 파일·줄이 달린 알림이 가요(누르면 그 줄이 열려요).
  - **두레에게 말로**: "두레야 민수님이 수정해야 하니까 여기에 메모 남겨줘" / "main.py 19번 줄에 메모 남겨줘" (채팅·음성·나만 보는 AI 모두). 워크스페이스에서 보내면 지금 열어 둔 파일·커서 줄이 함께 전달돼서 '여기·이 줄'을 알아들어요. 채팅의 [되돌리기]로 취소할 수 있어요.
  - **보기**: 코드를 가리지 않게, 메모가 있는 줄은 줄 번호 옆 가는 막대 + 줄 끝에 흐린 한 줄 미리보기(주석처럼)만 보여요. 막대·미리보기를 누르면 작은 메모 창, 마우스를 올리면 내용이 떠요. 아래쪽 `메모` 탭에는 전체 목록(열림·해결·전체, 이 파일만)이 있고, 누르면 그 줄로 이동해요. 파일 목록에는 메모 개수가 표시돼요.
  - **해결 · 고치기 · 지우기**: 해결 표시는 팀원 누구나, 글 고치기·지우기는 쓴 사람과 프로젝트 소유자만 할 수 있어요.
  - **줄이 밀려도 따라가요**: 코드를 고쳐 줄이 밀리면 에디터가 메모를 같은 줄에 붙여 두고 새 위치를 팀에 저장해요. 다른 사람이 고쳐서 줄 번호가 안 맞으면 메모에 적어 둔 줄의 글자(anchor)로 다시 찾고, 못 찾으면 주황색으로 알려 줘요. 파일 이름을 바꾸면 메모도 따라가고, 파일을 지우면 메모도 지워져요.
  - 실시간: 팀원이 달거나 해결하면 새로고침 없이 바로 보여요(`/ws/live` 의 `memos`). API: `GET/POST /api/projects/{id}/memos`, `PATCH/DELETE …/{memo_id}`.
- **실행 단축키** (`js/pages/workspace-keys.js`) — 맥은 Ctrl 대신 ⌘, Alt 대신 ⌥:

| 동작 | 단축키 |
|---|---|
| 실행 | `Ctrl+Enter` · `F5` · `Shift+F10` |
| 디버그로 실행 | `Shift+F9` |
| 중지 | `Shift+F5` |
| 저장 | `Ctrl+S` |
| 디버그 중 멈춘 상태 | `F5`/`F8` 계속 · `F10` 한 줄 · `F11` 안으로 · `Shift+F11` 밖으로 · `F9` 중단점 |

  파일 목록·터미널에 포커스가 있어도 워크스페이스 화면이면 동작하고(에디터 안에서는 에디터 명령이 한 번만 실행), 글자를 입력하는 칸에서는 가로채지 않아요. 브라우저의 F5(새로고침)는 워크스페이스에서 파일을 열어 둔 동안만 실행으로 바뀌어요. 도구막대의 키보드 버튼(폰에서는 숨김)에서 전체 단축키를 볼 수 있고, 실행·디버그·중지 버튼에도 단축키가 표시돼요.
- **단축키 바꾸기** — 설정 ▸ ‘워크스페이스 단축키’에서 실행·디버그로 실행·중지·메모 동작마다 원하는 키로 바꿀 수 있어요(동작당 최대 3개). ‘＋ 키 추가’를 누르고 쓸 키를 한 번 누르면 되고, 저장·복사 같은 예약 키·다른 동작과 겹치는 키·글자 하나만 누르는 키는 이유를 알려 주며 거부해요. 기본값에서 바꾼 것만 저장되고(`sync_ws_keys`) `/api/prefs`의 `keys`로 웹·앱이 같이 써요. ‘Ctrl’로 저장한 키는 맥에서 ⌘로 동작해요. 디버그 중 F8/F10/F11·F9는 고정이에요. 에디터의 실행·메모 키는 Monaco에 고정으로 박지 않고 `workspace-keys.js`가 한꺼번에 처리해요.

## 회의록 시트 · AI 인식 보정 · 캘린더 구분

- **회의록 작성 · 보기 · 수정이 같은 모양** (`js/pages/notes-sheet.js`): 제목 → 속성 줄(프로젝트·날짜·참석자) → 도구 막대 → 편집기. 작성 창과 보기/수정 서랍이 같은 부품을 쓰고, 칸(논의·결정·액션)의 색도 같아요. 쓰는 동안 오른쪽에서 **AI 가 지금 이렇게 읽고 있어요**(찾은 일정 · 취소로 본 줄)를 보여 줘요 (`POST /api/meetings/preview`, 규칙 기반이라 AI 한도를 쓰지 않아요). 임시저장은 이 기기에 실제로 저장돼요.
- **취소·정정·중복** (`api/services/note_prep.py`): `~~취소선~~` 이나 "○○ 취소"로 지운 일은 일정이 안 되고, 같은 일을 다시 적으면 한 번만, "다음 주 화요일로 변경"처럼 정정하면 마지막 날짜만 남아요. 회의록 · 채팅 일정 카드 · 두레 AI(채팅·음성) 모두 같은 규칙을 써요. 짧은 메모(`금까지`, `~다음주 월`, `11.20 2시`, `이번주 안에`, `월말`)도 읽어요.
- **수정하면 일정이 현재 글을 따라가요**: 더는 적혀 있지 않은 일정만 지우고 새로 생긴 일정만 추가해요 (팀원에게 가는 '새 일정' 알림이 중복으로 가지 않아요).
- **캘린더 구분**: 제목·원문에서 종류(마감·발표·회의·행사·일정)를 읽어 색과 아이콘으로 구분하고, 출처(AI 자동 · 팀 공유 · 나만 보기)와 작성자를 상세에 보여 줘요. 위쪽 '구분' 버튼으로 종류별로 걸러 볼 수 있어요. (저장 형식은 그대로)
- **아이콘 규칙**: 새 화면에서는 이모티콘 대신 서비스 공통 선 아이콘을 써요 → `uiIc('이름', 크기)` (`js/core/icons.js`, 커뮤니티의 `CM_ICON` 도 함께 사용). 새 아이콘은 `UI_ICON` 에만 추가하면 돼요. 움직임은 새로 만들지 않고 기존 것(`callPulse`, 서랍 슬라이드)만 써요.

## 웹 ↔ 설치한 앱(PWA) 설정 동기화 (`js/core/prefs.js`, `api/routers/prefs.py`)

웹과 앱은 브라우저 저장소가 서로 달라서, 거기에만 저장하던 설정은 공유되지 않았어요. 이제 같은 값을 서버(`/api/prefs`)에도 보관해요.

- **동기화**: 홈 위젯(보이기·순서·크기) · 홈에서 고른 프로젝트 · 캘린더 보기(숨김·색·선택) · 저장한 공모전 · 테마 · 프로젝트별 마지막 파일 · 채팅 읽음 위치
- **동기화 안 함** (기기마다 달라야 해서): 화면 크기 배율 · 움직임 · 효과음 · 내 PC 실행기 · 미리보기 크기
- 저장하는 코드는 그대로 두고 저장한 직후 `prefsPush('키')` 한 줄만 불러요. 키마다 **나중에 바꾼 쪽**이 이기고, 한쪽에서 바꾸면 실시간 연결(`/ws/live` 의 `prefs`)로 다른 쪽이 바로 따라와요.
- 처음 연결하는 기기: 서버에 값이 있으면 받아 오고, 없고 내 기기에 저장해 둔 값이 있으면 올려요. 다른 계정으로 로그인하면 이 기기에 남은 이전 계정 설정은 지워요.
- 새 설정을 동기화하려면 `PREFS.defs` 에 `read/write/wipe` 를 추가하고, 서버 `routers/prefs.py` 의 `CHECKS` 에 값 검사를 넣으면 돼요.

## 두레(채팅 AI)가 쓸 수 있는 자료·일 (`api/services/chat_ai.py`)

AI 호출은 요청당 **1회** 그대로(Gemini 무료 한도 보호). 대신 **말한 내용에 맞는 자료만** 골라 함께 건넵니다.

| 이런 말이 나오면 | 함께 보는 자료 |
|---|---|
| 커뮤니티·게시글·모집·추천 … | 공개 커뮤니티 글 40개 + 내 프로필(기술·소개)·참여 프로젝트 → 맞는 글을 골라 **눌러서 열리는 칩**으로 |
| 공모전·해커톤·대회 … | 마감 임박 공모전·행사 25개 |
| 파일·코드·`main.py`·`19번 줄` … | 프로젝트 파일 목록 + 말한 파일의 내용(줄 번호 포함) |
| 전체·모든·내 일정·이번 주 … | 내가 속한 모든 프로젝트의 2주 일정 |
| 알림 / 저장한 글 / 대화·어제·누가 … | 내 알림 / 북마크 / 더 오래된 팀 대화 |

- **팀원에게 요청 전달**: "민수님께 main.py 19번 줄 수정 부탁한다고 전해줘" → 그 팀원에게 파일·줄 위치가 달린 알림(누르면 그 줄이 열림). 되돌리기 가능. AI 가 파일을 직접 고치지는 않아요.
- **AI 를 안 불러도**: 평범한 팀 대화의 "민수님 main.py 19번 줄 수정 부탁드려요"처럼 `이름+님/씨` + 실제 있는 파일 + 부탁하는 말이 모두 있으면 규칙으로 알림 (AI 호출 없음, 같은 요청은 10분 내 중복 방지).
- 읽기 범위는 **호출한 사람이 볼 수 있는 것만**: 내 프로젝트 · 공개 글 · 내 알림. 남의 개인 AI 대화, 다른 프로젝트 파일·일정은 건네지 않아요.
- 알림 링크 형식: `file:프로젝트번호:줄:경로` → `wsJumpTo()` 가 워크스페이스를 열고 그 줄로 이동.

## 화면 주소

| 주소 | 화면 |
|---|---|
| `/app` | 로그인 전: 서비스 소개(첫 화면) · 로그인 후: 홈 (로그인해야 쓸 수 있고, 게스트 둘러보기는 없어요) |
| `/app?pwa=1` | 브라우저에서 '설치한 앱'처럼 미리 보기 (인사 화면 → 로그인 전이면 바로 로그인 화면). `?splash=1` 은 인사 화면만 |
| `/app/login` | 로그인 |
| `/app/workspace` | 워크스페이스 (코드 에디터) |
| `/app/meetings` | 회의록 |
| `/app/calendar` | 캘린더 |
| `/app/events` | 이벤트·공모전 |
| `/app/community` · `/app/community/12` | 커뮤니티 · 글 12번 |
| `/app/mypage` · `/app/admin` | 마이페이지 · 팀 관리 |

주소를 직접 열거나 새로고침해도 그 화면이 열리고, 브라우저의 뒤로/앞으로 가기도 동작합니다. 새 화면을 추가하려면
`index.html` 에 `<section class="view" data-view="이름">` 을 만들고 `js/core/router.js` 의 `ROUTES` 에 주소를 한 줄 넣으면 됩니다.

## 어떻게 합쳐지나
- 서버(`api/main.py`)가 `manifest.json` 순서대로 파일을 이어 붙여 `/static/bundle.css`, `/static/bundle.js` 로 내려줍니다.
  파일이 바뀌면 자동으로 버전(`?v=`)이 바뀌어 브라우저가 새로 받습니다. 별도 빌드 도구(npm 등)는 필요 없어요.
- 합치는 순서가 곧 실행 순서입니다. 예전 한 파일일 때와 똑같이 동작하도록 원래 순서를 그대로 지켰습니다.
- `index.html` 을 더블클릭해서 여는 방식은 더 이상 쓰지 않습니다. `./run.sh` 로 서버를 켜고 `http://localhost:8000/app` 으로 접속하세요.
